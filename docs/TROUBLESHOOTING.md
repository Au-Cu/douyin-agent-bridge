# 故障排查

## Windows：首次点击“打开抖音窗口”没有反应

先查看面板错误、任务栏中的 Edge 和本机日志。0.12.0 修复了一个已复现的失败路径：首次页面导航失败后，浏览器资料已创建，旧版再次点击却直接返回，不重试导航。新版会重新显示已有窗口并重试失败页面，不需要删除浏览器资料。

这不是对所有“没有反应”反馈的统一归因。现有 Windows 源码包支持 x64 和 ARM64，安装器按当前 Node 架构选择依赖；没有证据表明该问题需要另一份架构专用源码。可用 `node -p "process.platform+' '+process.arch"` 检查架构，再运行 `npm run doctor`。Windows ARM64 已验证干净资料能打开 Edge；Windows x64 由 CI 检查，其他机器仍需实际核验。

## Mac：Safari 不响应或提示 Apple 事件无权限

Safari 设置中先在“高级”显示开发者功能，再到“开发者 → 自动化”启用“允许来自 Apple 事件的 JavaScript”；首次弹出 macOS 自动化授权时允许启动助手的终端控制 Safari。助手只控制自己创建并带有识别标记的窗口。账号登录由当前 Safari 个人资料管理，需要与主号隔离时先在 Safari 选择助手专用个人资料，再打开助手窗口。退出隐私浏览会丢失该会话，不适合需要长期保持登录的助手。

PR 作者报告 Mac 版曾完成真实账号文字与表情验收；合并版自动化测试与本次真实账号核验分开，视频地址提取、原片下载与全时段视觉学习仍需在本机用真实视频核验。视频地址提取或下载被 Safari/平台限制时，任务会报告失败，不会用少数预览帧冒充完整视觉分析；表情或回复未能核验时也不会盲目重复。请在本机检查 Safari 中的登录和验证状态。

## Mac：打开抖音窗口后提示“请在 Safari 设置中允许来自 Apple 事件的 JavaScript”

这句提示曾经具有误导性。Safari 26 的“新建文档”会把抖音私信页开成当前窗口里的一个新标签，而不是第一个标签；旧版本按标签 1 读取，读到别的页面后报“来源已变化”，最后却显示成这句与 JavaScript 无关的提示。助手现在按页面地址定位标签，并把窗口和标签位置一起保存；你在 Safari 里自己挪动标签后，重启助手会重新定位同一个页面，不会再开一个重复页面。

如果确认 JavaScript 开关已经打开仍然失败，看控制台事件里有没有“未能在 Safari 中找到抖音私信页面”——那说明那个标签已被关闭或页面没有加载出来，需要重新打开助手窗口。

## Mac：回复一直排队，提示“私信输入框有未发送的草稿，请先处理”

助手不会覆盖你在抖音输入框里还没发出的文字。请先在 Safari 里处理掉草稿（发送或删除），发件箱会在几秒内自动重投。

程序仅恢复已核验属于本轮的草稿；用户文字或媒体草稿不会被覆盖。若上次发送是否成功不明确，先核对原聊天并在面板确认，不要直接清草稿并重发。


## 未安装 Node 或版本过低

安装 Node.js 24.5.0+，重新打开终端，再运行 Install.ps1。终端用 node --version 检查。安装器和服务支持路径中的空格与中文；不要把解压目录误当成需要共享的账号资料。

## Codex 待登录或连接失败

先 npm ci，再 npm run codex:login，用自己的 ChatGPT 账号完成官方登录。登录后重启助手并运行 npm run doctor。项目固定安装官方 @openai/codex 0.166.0，避免 Windows 的全局 .cmd 路径问题。需要使用另一个已安装版本时，可设置 CODEX_BIN 为 codex.exe 或官方 codex.js 的绝对路径；不需要复制登录令牌到项目。

## 端口已经占用

用 powershell -File .\Start.ps1 -Port 39362 换端口。同一套数据只允许一个进程使用；相同账号数据的其他代码副本会打开已有面板。隔离账号要同时指定不同 BRIDGE_DATA_DIR 和端口。升级旧版本前先正常停止它。

## 重启后像新安装一样，资料和配置都不见了

旧版按源码目录读取 data/；同名“启动助手.cmd”放在不同文件夹中，就会读到不同数据。先保留全部旧目录，检查哪个目录有原来的 bridge.sqlite、knowledge/ 和 browser-profile/，不要重新覆盖它们。

0.12.1 默认把 Windows 数据固定在 %USERPROFILE%\.douyin-codex-bridge\data，避免商店版 Codex 对 AppData 的文件重定向造成“同路径、不同文件”。升级会发现旧 AppData 或 Codex 应用私有目录中的资料，完整迁移并保留原目录；多套不同资料并存时停止自动选择，避免恢复错账号。需要选择完整旧目录时，先正常停止旧助手和共享桌面，再运行 node scripts/storage.mjs --migrate-from "旧目录的完整 data 路径"。已有账号或记忆的目标目录不会被覆盖。

共享入口提示“未找到共享连接配置”，但面板已经准备过时，也可能属于上述 Windows 重定向问题。更新到 0.12.1 后重新准备连接，原生启动入口使用实际物理路径。可用 powershell -File scripts/StartSharedCodex.ps1 -CheckOnly 只核验配置和程序路径，不启动或终止桌面。若仍失败，提示会显示读取的配置路径。

已保存的配置即时提交，不等退出时才写入；强制关机后，正在执行或送达的操作可能需要人工核实。可读配置损坏时从数据库恢复；数据库完整性检查失败则保留现场并停止，避免空库覆盖或旧任务重跑。面板提供状态快照，完整备份需正常停止后复制整个固定数据目录。

保存浏览器资料后会尝试恢复抖音登录；平台撤销会话或要求验证时仍需重新登录。重新登录不会清除本机学习资料和需求。

## 换号后提示 access token could not be refreshed

先在本机 Codex 完成有效登录。桥接检测到登录文件变化时会重建自己的 app-server 连接，并保留调度聊天、抖音绑定、目标名单及视频资料。无需删除 data/ 或重建全部配置。

在抖音发送 /重新连接，或点控制台“重新连接 Codex”。如果提示等待任务结束，先让已有任务完成；不会为了换号中断或重放执行任务。暂停的视频可在连接恢复后自动续做，也可以发送 /继续视频。

系统凭据库登录或同一账号额度恢复可能不会改变 auth.json，使用手动重连入口即可。若重新连接后仍提示登录失效，说明新进程也无法使用当前登录：重新完成 Codex 官方登录，再重连。不要复制、编辑或上传 auth.json、Cookie 或令牌。

群聊使用另一套独立的受限连接。0.12.0 会在下一条新消息到来时重建失效连接，且每次重连重新导入当前登录到内存；面板“重新连接 Codex”同时使群聊连接在空闲后重新核验。换号期间已在执行的消息不跨账号续跑，失败或结果不明的消息不会自动重放。群聊与个人 Agent 的模型设置独立，面板会区分认证错误和额度限制，并注明群聊模型；不能仅凭旧版合并提示认定新账号额度不足。

## 识别不到消息

确认使用的是项目打开的 Edge 窗口、登录助手账号、已打开主号会话，并由主号发来一条消息。绑定后再开启监听、转发新视频。0 条识别消息不代表接通。登录或验证码由你在项目窗口完成；桥接不会自动绕过验证。

## 贴表情失败

程序右键消息内容，按阶段选择可核验的 OK、眼睛/奋斗、撒花/完成表情，并确认反应条出现；需要时展开更多表情。视频中央播放控件不会作为右键目标。当前进度只贴表情，不能核验时在面板记录，不自动改为文字或反复点击，避免撤销已有反应。已有同款表情但无法确认归属时也不会盲点。

快捷栏会按使用情况变化。程序支持无文字的圆形“更多”按钮，并只点击具体表情图标，不点击包含多张图标的整行或网格。弹出会话覆盖背景时选择前景可操作的聊天；确定尚未点击且受遮挡的回执最多退避 3 次。已经点击但结果不明的回执仅保留核实，不能自动重试。任务卡把实际执行进度、分段回复和表情送达分别显示，错误详情默认折叠。

## 一直排队或 already has an active writer

发送 /状态 查看未提交任务的编号、标题和阻塞原因，例如“任务 5：修改首页动画”。不同聊天可并行，只有相同目标聊天才等待写入权；其他项目运行不构成全局锁。目标聊天被占用时不强抢，会退避并在达到上限后暂停。释放同一聊天的原写入者后，用 /重试 5 恢复确定未提交的任务。执行结果不明、有回合编号的任务需先核实，不能强行重跑。

桌面应用即使显示空闲，也可能保持该聊天的独占写入连接，独立启动另一个 app-server 仍会冲突。0.12.0 请按 README 的“接续桌面 Codex 中的项目聊天”准备共用服务，完全退出桌面应用后通过共享入口启动。不会删除锁文件或结束其他项目进程。共享入口未启用时只保留未提交队列；不得把排队、组件自检或连接成功表述为项目实际执行完成。

对应任务卡的“写入调度”显示最近检查时间、结果与下次计划；展开“查看调度记录”可查看逐次结果。暂停后不会再显示下次自动重试。旧版本没有保存的早期明细不能恢复，面板会明确说明。

## 回复还没发完就重复提交

看消息开头的“回复 1/3 段”和最后的“末段”，完成表情在全部任务及回复确认后才出现。原要求尚未结束时，同样的要求会关联原操作；新增修改会保留为补充。明确重新做会启动新一轮。后台只记录重复关联，不把催办反复加入模型上下文。

## 下载模型、npm 或视频工具失败

首次安装需要访问 npm 和 GitHub。检查网络后重试。Node 下载支持系统环境里的 HTTP_PROXY/HTTPS_PROXY（不要把代理密码写进仓库）。npm 的代理按自己的 npm 配置处理。模型压缩包校验失败时，将报错的归档移出 data/models 后重新安装，不要继续解压损坏文件。

## Codex 额度不足、视频只完成部分

已完成段落保留。额度恢复后在抖音发送 /继续视频，也可在控制台续做。较高帧率和较长视频会消耗更多额度。不要把标题、字幕或少量预览帧当成已经完成视觉学习。

## 任务或回复需要核实

发送回执丢失、提交后断线等情况不会自动重发。先去原抖音或 Codex 聊天确认实际结果，再使用控制台的核实选项。不要直接改数据库状态绕过保护。

## 更新版本

先正常停止并备份面板显示的固定数据目录，再 git pull 或更新源码，运行 npm ci。固定数据与源码分开；不要覆盖为别人的浏览器资料。正常停止保留恢复监听的意图；手动暂停则在重启后保持暂停。

## 消息分到了错误需求

发送 /状态 查看当前需求；用 /找 查目录，再 /切换 需求编号，例如 /切换 2。旧 ID 仍兼容。独立的新目标可直接 /新建 标题。遇到待澄清的消息，切换或新建会把最近一条待选择消息归入你指定的需求。控制台也支持同样操作。关闭 /分聊 关 可以固定当前需求，但上下文预算仍然生效。

## 模型、强度或快速模式保存失败

控制台点“刷新模型名单”，或在抖音发送 /模型、/强度，按当前登录支持的完整模型 ID 和档位设置。不同模型支持的档位、图片输入和快速服务层可能不同；切换账号后也可能变化。程序不会静默换成另一个工作模型。先 /快 关，再选择不提供快速模式的模型。

## 为什么出现同名的第 2 个会话

这是同一需求的预算续接，原会话保留。新会话收到简短交接和完整记录入口，需求 ID、视频关联与目标名单不变。临时路由、视觉分段和摘要使用结束即卸载的会话，不会接到这个长历史里。模型读取大量文件或工具输出时，实际上下文仍可能在单轮中增长；系统在轮次之间检查并交接。

提交 issue 时提供版本、Node/Windows 架构和脱敏错误描述。不要上传 data/、个人聊天标题、视频、Cookie、签名媒体地址或 Codex 认证文件。

## 普通聊天 AI

- 先在面板点“配置一个单聊或群聊”，再去抖音窗口选聊天；选择期间暂时暂停轮询，避免自动切回其他会话。完成选择后恢复，或等待 5 分钟自动恢复。
- 无法核验助手身份时，从助手账号在目标聊天手动发送一条普通消息，再点“读取当前抖音聊天”。聊天类型、助手 UID 或 @ 元数据缺失时不会按昵称猜测，也不会回复群聊的普通消息。
- 群聊默认通过抖音的原生 @ 选择账号；在每个群聊的“回复范围”可改为回复所有新消息。仅 @ 模式下，@全体、引用别人的 @ 或直接输入“@昵称”不会触发。网页版改版导致提取失败时，在本机运行记录查看原因，不要关闭身份校验。
- 个人 Agent 使用现有的绑定用户单聊。普通聊天不执行 /派给、/模型、/重试 等个人 Agent 控制命令；这些输入只作为聊天内容，也不能切换权限。需要学习原视频或处理项目时，用绑定用户的个人 Agent 会话。
- 模式切换会停止未发送的旧聊天结果并隔离上下文。个人 Agent 的待办、资料与需求不会被删除；切成普通聊天时旧待办暂停，切回个人 Agent 后才可继续调度。
- 普通聊天的独立 Codex 目录不会复制本机 auth.json。当前仅支持文件保存的本机 ChatGPT 登录；钥匙串独占登录或无法共享的账号会停止启用。不要把 auth.json、访问令牌或刷新令牌粘贴到聊天、工单或仓库。
- 普通聊天报“送达需核实”时先检查抖音，再在面板确认。已经提交但结果不明的回合不会自动重跑，表情点击不明也不会重复点击。
- 升级依赖后普通聊天停止启用：先运行 npm ci 恢复固定的 Codex CLI 0.166.0。工具隔离依赖该版本的已验证协议，升级前需要在两个系统运行实际 CLI 工具清单测试。


## 群聊切换、引用与代码沙箱

- 侧栏未读筛选优先读取当前 unreadCount。SDK 的 badgeCount 可能是已读后仍保留的累计计数，不能把它当成当前红点。未读字段或身份无法核验时仍低频补查，不能仅凭没有红点认定没有消息。
- 切换聊天后会等待短暂稳定采集。发送与其送达核验占用同一操作锁，视频专用标签页和模型推理不占聊天锁。浏览器验证码需要用户在项目窗口手动完成，不会由程序绕过。
- 群聊每一段回复均核对原生引用消息编号；入口或引用指针无法核验时保留已生成结果，修复发送路径后续发，不重新运行模型，也不降级为无引用发送。
- 代码沙箱需要启动 Linux 容器引擎并准备官方 Python 镜像。标准 Docker 后端运行 npm run setup:sandbox；专用 Windows WSL2 后端运行 npm run setup:sandbox -- --wsl。固定发行版名称为 codex-chat-sandbox，关闭 automount 和 interop，镜像准备成功后保存后端与不可变镜像 ID。
- 引擎、镜像或隔离检查失败时，代码执行保持关闭；不会回退到宿主机。Docker Desktop 由软件自身维护更新；专用 WSL 引擎由本机用户维护，使用静态二进制安装时也需要手动更新安全补丁。

- 群聊送达误报时，可点普通聊天记录的“核验原聊天”：只读取原聊天，核对唯一的完整正文、结构化 @ 前缀、发信账号和原生引用 ID 后确认送达；无法唯一核实则保留现场，不重发。

- 群聊的原生引用可能自动留下仅含 @ 的编辑节点。程序核对当前原消息 ID 与 SDK 发信账号后，保留这个节点继续填写；不按昵称猜账号，不覆盖手写文字或媒体草稿。被回复的消息本身有旧引用时，以输入框原生预览对应的消息 ID 为准，不误用它嵌套的旧引用。

## DSH 后端与模型选择

个人 Agent 后端保存后重启生效；普通聊天后端从下一轮生效。BRIDGE_HARNESS 环境变量优先于面板。既有需求、续开会话和已授权目标保留原后端，切换不会搬运历史或自动重跑。Codex 与 DSH 的 Agent/聊天模型组合分别保存。

未找到 DSH 时先在原生应用完成安装与登录，或让 DSH_BIN 指向官方 CLI lib/bin.js/可执行文件。Windows npm .cmd 入口会安全解析到 JS，不通过 shell 拼接聊天内容。普通聊天和视觉工作器仅启用验证过的 0.2.1-rc.5 配置；升级后不兼容时保持关闭，不放宽权限。

视觉不可用时选择实际支持图片的模型，并用 /续看 续做已保存片段。不会将只有文字能力的模型冒充为已看过视频。DSH 现有桌面会话仍占用时需先在原生应用结束该聊天的运行；不能删除写入锁或把结果不明的任务重试。原生 ACP 不提供归档和完整历史导出，面板对此作本地可恢复归档及桥接证据保存。
