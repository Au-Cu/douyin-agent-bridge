# Private state and vulnerability reports

Project dispatch in 0.12.0 uses the desktop's shared app-server through a local named pipe or Unix socket, guarded by a random capability in private `desktop-shared/` state. Never publish that directory. Request and callback IDs are translated per connection; native tools and approvals remain with the desktop. Interruption requires the exact bridge-owned turn. Disconnecting the bridge never terminates another desktop chat. Desktop cutover is manual; the launcher refuses to replace a running desktop. Ordinary chat remains on its separate restricted process and has no access to the shared transport.

Report vulnerabilities through GitHub private vulnerability reporting when available. Otherwise describe the affected component in an issue without credentials or private account data.

Never attach data/, browser profiles, cookies, Codex auth.json, signed media URLs, chat databases, private videos or complete diagnostic bundles to issues or pull requests. Use synthetic messages for reproductions.

The console listens on 127.0.0.1 only. It is designed for a personal computer and a dedicated Douyin assistant account. Only the bound owner can authorize work; target chats require an explicit allowlist. Do not expose it through a public tunnel or shared host.

Reply-only conversations are explicitly selected in the local console using observed platform identities. Group messages default to native structured mentions matching the verified assistant UID; a local per-group option can instead allow all new incoming messages. Unknown group type or account identity always fails closed; missing mention metadata fails closed in mention mode. Names and plain text mentions do not grant access. Personal Agent retains the existing bound-user single-chat boundary.

Native restoration prefers exact SDK conversation IDs and always verifies the selected chat before sending. An assistant UID witnessed in outgoing platform messages can be carried within the same authenticated browser session when virtualized history hides those messages. Account-cookie change markers stay local and are never returned in diagnostics; logout, a changed marker or conflicting outgoing identities invalidate the witness. If no account marker is available, reuse is restricted to the same live document. The ordinary-chat model cannot access or change any of these bindings or its own model defaults.

Reply-only inference runs in a separate Codex process and CODEX_HOME, with an empty working directory, fresh ephemeral threads, bounded per-chat context and a sanitized model catalog. Host shell and apply_patch are independently disabled; MCP, apps, plugins, hooks, skills instructions, personal memory, computer tools and delegation are unavailable. The only allowed capabilities are Codex's hosted public web search, bounded pure arithmetic, a clock, and optional verified disposable container Python. Client requests outside that exact allowlist, including approvals and dispatch, are denied. A read-only sandbox alone is not considered sufficient isolation.

The pinned CLI is exercised by an offline local backend test on Windows and Mac: it inspects the actual tools array and sends a forged exec_command call to verify that no host executor is registered, while the permitted calculator and clock still work. External ChatGPT access tokens travel through local stdio only and are not persisted in the isolated profile or sent into the code container. The normal login, refresh token and personal project state are not copied there. No API key is required. File-backed local ChatGPT auth is currently required for this opt-in feature; unsupported keyring-only auth is rejected.

Container execution is a fixed broker, never raw model-supplied Docker arguments: verified immutable image ID, no mounts, no network, no host PID namespace, no device, no Docker socket, no host credentials, non-root UID, dropped capabilities, no-new-privileges, read-only root and an ephemeral 32MB /work tmpfs. Memory/CPU/process/output/time budgets are bounded. Interrupted containers are removed only after verifying their random name and ownership label; unknown cleanup retains a local audit record. The tool never falls back to host code execution. A real Linux Docker CI test probes these boundaries and host sentinel preservation; per-device Docker readiness is checked separately.

Native group replies carry the exact triggering platform message ID in every persisted segment. Composer and sent-message quote IDs must match; an uncertain send is never replayed. Message collection and UI side effects hold complete browser-operation leases, and inbox unread counts optimize navigation without replacing periodic reconciliation. Model inference and independently owned video tabs do not hold the inbox lease.

Changes to a conversation's mode/revision fence queued or late reply-only results. Submitted uncertain inference or delivery is retained rather than silently replayed. Native UI selection, verification and send/reaction actions are serialized to prevent replies from being written into a different chat. This does not guarantee factual answers or prevent social manipulation in generated text; it removes project and computer execution authority from the ordinary chatbot.

Optional DSH never replaces Codex without explicit local configuration. Thread IDs are namespaced and model settings remain independent; existing Codex targets continue through the desktop shared connection. DSH resumes only the exact native session/cwd; an occupied session is not forcibly taken over. Submission journals, owned-turn cancellation and uncertainty fences survive restarts. Native archive is unavailable in DSH and is never simulated as a successful RPC; local archive is reversible.

DSH reply-only and read-only workers use audited @deepseek-ai/dsh 0.2.1-rc.5 with a fresh DSH_HOME and empty workspace. The final plugin graph is checked: user plugins, skills, host filesystem/shell/computer/project tools and subagents are disabled. Only advertised managed public tools and optional verified container Python are exposed to ordinary chat; unexpected native tools terminate that restricted connection. Native credential lookup references the original local credential file through the trusted service without copying credentials or placing them in model input. The MCP callback requires a random per-session capability, a currently running owned turn and an exact registered tool. Temporary image analysis carries actual image bytes and managed visual tool results, without granting host file tools to the model.

DSH wire tests run the pinned real ACP runtime against a local synthetic provider: empty/public/container tool lists, forged host execution, inline and tool-result images, and refusal of a text-only route. No real model login or contact is used. These tests establish protocol/tool boundaries, not factual accuracy or real-account Douyin delivery. DSH is an explicitly chosen external inference provider; service/account terms remain the user's own.
