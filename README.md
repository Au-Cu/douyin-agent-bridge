# 抖音 Agent Bridge

[![CI](https://github.com/Au-Cu/douyin-agent-bridge/actions/workflows/ci.yml/badge.svg)](https://github.com/Au-Cu/douyin-agent-bridge/actions/workflows/ci.yml)
[源码发行包](https://github.com/Au-Cu/douyin-agent-bridge/releases/latest) · [故障排查](docs/TROUBLESHOOTING.md) · [MIT](LICENSE)

在手机抖音里，把视频私信转发给自己的助手账号。电脑上的桥接读取原视频，让你自己的 Codex 或 DeepSeek Harness 理解画面和口播，并在原私信里回复。你明确发出指示后，它可以把原片、视觉资料和任务交给你允许的其他助手聊天。

你不需要先截图、摘字幕或手动概括视频。把视频当作图片参考一样转发，随后直接说“按这个做”“比较刚才两个视频”或“把这个交给网站项目”。

也可以在面板中为指定单聊或群聊启用普通聊天 AI。它使用所选后端的本机登录，仅回复该聊天的消息；群聊默认仅在原生 @ 助手时回复，也可为每个群聊选择回复所有新消息。现有的视频学习与项目处理称为“个人 Agent”，仍使用绑定用户的单聊。

这是运行在个人电脑上的社区项目，依赖抖音网页版结构。提供 Windows x64 / ARM64 和 macOS Apple 芯片版本；Windows ARM64 已做真实账号验收。PR 作者报告 Mac Safari 版已完成真实账号的文字往返和三段表情回执；本次合并的真实账号复核与自动化回归分开记录。视频地址提取、下载与全时段视觉学习仍需在自己的 Mac 上用真实视频核验；无法获取原片时会停止并报告，不会假装完成视觉学习。Linux 尚未提供安装入口。不是抖音、OpenAI 或 DeepSeek 官方连接器。

## 需要准备

- Node.js 24.5.0 或以上：[官方下载](https://nodejs.org/)。安装后重新打开终端。
- 正常联网并在使用期间保持开机的电脑：Windows 使用 Microsoft Edge；Apple 芯片 Mac 默认使用系统 Safari。
- 自己已开通 Codex 使用权限的 ChatGPT 账号。项目会安装固定版本的官方 Codex CLI，复用本机 Codex 登录与聊天数据，无需单独配置模型 API Key。也可以改用本机 DeepSeek Harness，见[改用 DeepSeek Harness](#改用-deepseek-harness)。
- 一个用来接收视频的抖音助手账号；主号和助手账号互关。手机可以是 iPhone 或安卓。

默认由 Codex 完成视觉理解和任务执行，口播使用本机 SenseVoice 转写；默认路径不调用第三方模型。只有你明确选择 DSH 后端时，相应内容才会提交给你在 DSH 配置的模型服务，使用该服务的额度。不会在额度不足时自动把 Codex 任务转给 DSH。耗时和额度消耗取决于视频长度与采样密度。

## 接续桌面 Codex 中的项目聊天

0.12.0 的项目派发与桌面应用共用同一个本机 app-server，避免桌面空闲聊天仍占有写入权时，独立进程报 `already has an active writer`。不同聊天可以并行；同一聊天已有回合运行时等待。结果与中断均核对原聊天和具体回合。

1. 更新源码并运行 `npm ci`。在面板“连接助手”中点击“准备桌面共享连接”，或在桌面 Codex 的项目终端运行 `npm run setup:desktop`。
2. 等桌面聊天完成当前工作，完全退出桌面 Codex（Windows 包括托盘）。Windows 运行项目根目录的 `启动共享Codex.cmd`；Mac ARM64 运行 `start-shared-codex-mac.command`。入口显示桌面窗口，并启动或复用助手服务、自动打开控制台；Mac 默认使用 Safari。只有共享服务在后台运行。入口只给此次新桌面进程设置连接，不改全局环境，不删除聊天或登录。
3. 在自动打开的助手控制台点击“检查共享连接”。确认连接后，可点击“恢复未提交的受阻任务”。该按钮仅恢复有明确未提交证据、未归档且未中断的写入冲突任务；结果不明的任务需先核实。若桌面已经运行，重复点击入口只请求显示现有窗口并打开控制台，不会终止工作，也不会把已有进程自动切换成共享连接。

普通的“启动助手”入口仍负责启动桥接和抖音窗口。只需每次启动桌面 Codex 时使用共享入口；启动顺序不限。未通过共享入口打开桌面时，项目派发会保留队列并明确提示。视频分析和普通聊天不受这个入口限制。普通聊天继续使用独立的受限进程，不接入桌面共享服务。

共享服务只监听本机私有命名管道或 Unix socket，使用私有数据目录中的随机能力令牌。不得分享 `desktop-shared/`。如未找到桌面程序，可运行 `npm run setup:desktop -- --codex "桌面自带 Codex 可执行文件" --app "桌面应用可执行文件"`。更新桌面应用后若原程序路径失效，重新准备连接。

## 为单聊或群聊启用普通聊天

1. 在 39361 面板展开“启用 AI 的抖音聊天”，点“配置一个单聊或群聊”。轮询与发送会暂时暂停，最长 5 分钟，方便在抖音窗口选聊天。
2. 在助手登录的抖音窗口打开目标聊天，点“读取当前抖音聊天”。如果无法核验助手账号身份，请从助手账号手动在该聊天发一条普通消息，再读取。未能核实聊天类型或账号时不会启用。
3. 选择“普通聊天 AI”，保存并启用。按需开启总监听。其他未启用的聊天不会收到回复，启用前的历史消息会跳过。
4. 群聊默认使用抖音原生的 @ 选择助手账号后发送消息；也可在该群的回复范围选择“回复所有新消息”。仅 @ 模式下，单纯输入“@昵称”、@全体、引用别人的 @，都不会触发。暂不支持的网页消息格式会保持静默，并在本机记录原因。

“个人 Agent 的模型与需求对话”设置个人 Agent 默认模型；“启用 AI 的抖音聊天”中设置普通聊天默认模型。两种模式的模型、推理强度和快速模式分别保存，重启后恢复，当前回合不会被中途切换。首次升级会把此前共用的组合复制为普通聊天的初始配置，之后修改任意一组不会改变另一组；普通聊天模型留空时跟随所选后端默认模型。Codex 与 DSH 的两组默认组合分别保存。

群聊恢复按实际会话 ID 定位，标题带群人数、装饰或与侧栏显示不同也不会按昵称猜测。已验证的助手身份在同一登录会话内保持，不依赖某条自己发出的消息一直留在可见范围；退出登录、账号标记变化或无法确认身份时停止复用。

每个聊天可单独停用或更改模式。个人 Agent 就是原有的绑定用户单聊，继续使用原有命令、视频、需求和授权目标；它不会扩展给其他联系人或群成员。绑定用户改成普通聊天时，尚未开始的个人 Agent 工作保留并暂停；正在执行或发送的个人 Agent 工作需先结束或中断。模式只能在面板修改，聊天内的提示词、/派给 等命令不能提权。

Codex 普通聊天使用独立的 CODEX_HOME、空工作目录和临时回合，只开放明确的工具白名单：公开网页检索、纯数学计算器、时间查询，以及可选的隔离容器 Python。本机终端、文件修改、电脑控制、浏览器操作、MCP、插件、钩子和跨聊天派发均关闭，也不提供个人 Agent 的知识库、项目资料和指令。每轮最多带上本聊天最近 6 次已送达交流，并限制总长度；引用反馈时只查本聊天的完整反馈记录。模型和推理强度由你独立选择，不会因群聊身份而被程序调低。

每个群聊可独立选择“仅被 @ 时回复”或“回复所有新消息”，默认前者。修改回复范围从新消息起生效，保留正在生成和发送的回复、聊天历史及权限隔离；两种方式都不处理助手自己的消息。

左侧原生未读数字用于减少会话切换：确定无未读时跳过空闲聊天，有未读才优先采集；仍每分钟补查，防止手动打开聊天清除红点后漏读。侧栏无法核验时保留轮询。切换后的短暂稳定采集、输入、发送和送达核验共享完整操作锁；模型分析和独立视频标签页不占用聊天锁。每段群聊文字都原生引用触发消息的 ID，发前、发后核对指针；不能核验时保留待处理或待核实状态，不假装完成或重复发送。

普通聊天目前只处理文字和分享卡片标题，不会下载或假装看过视频。需要完整视觉学习和项目落地时，请在绑定用户单聊使用个人 Agent。收到、真正运行、全部分段送达分别使用原生“👌、奋斗、🎉”回执；未能核验的表情不会盲目点击。送达不明时保留现场，不自动重发，可在面板的普通聊天记录中人工确认。

Codex 模式无需模型 API Key。桥接只通过本机管道把当前 ChatGPT 访问令牌交给隔离的 Codex 进程，令牌不进入模型提示、不写入隔离目录；原登录与刷新令牌保留在本机原 Codex 中。只使用系统钥匙串、没有本机 auth.json 的登录暂不支持共享到隔离聊天，此时会停止启用。可通过官方 CLI 的文件登录方式登录后重试，不要手工复制认证文件。

验证隔离权限的回归测试随 `npm test` 执行：实际启动固定 CLI，对本机合成后端核验工具白名单，并伪造本地执行调用验证无法执行。关闭公共工具的临时配置仍核验 tools 为空。可选 `npm run test:chat:live` 使用本机登录验证独立回合和安全工具，不给任何真实抖音联系人发消息。单元测试、本机 Codex 验证与真实抖音群聊收发是不同的验收项。

## 可选的本机代码沙箱

先安装并启动支持 Linux 容器的 Docker 引擎。Windows ARM64、Mac Apple 芯片可使用对应架构的 Docker Desktop；镜像与应用源码分开安装。Windows 也支持专用的 WSL2 发行版 codex-chat-sandbox：关闭 Windows 盘自动挂载和 Windows 程序互通，在其中安装并启动 Linux Docker Engine，再运行 npm run setup:sandbox -- --wsl。该后端只连接这个固定名称的发行版，不改变已有 Docker 上下文或其他 WSL 环境。

运行 `npm run setup:sandbox`，或在面板点“准备容器镜像”。若镜像已通过可信渠道预先导入，可用 npm run setup:sandbox -- --cached 核验本机镜像；WSL 后端同时加 --wsl。默认准备过程下载官方 Python slim 镜像并保存不可变的镜像 ID。检查就绪后，在普通聊天配置中勾选“启用容器代码沙箱”并保存。镜像的准备、能力开关均只能从本机配置触发，模型没有安装软件、选择任意镜像或运行 Docker 命令的权限。

每次调用创建一个新容器：无网络、无宿主目录挂载、无 Docker socket、无用户文件/账户/登录令牌、非 root、只读根目录，仅 /work 有 32MB 临时空间，限制 256MB 内存、1 CPU、32 个进程和 30 秒运行时间。结果只通过有限长度的标准输出返回；临时工作空间随容器结束消失。环境不可用时停止代码调用，不回退到宿主 Python 或终端。公开联网检索由所选后端已开放的公开搜索工具提供，与无网络的代码容器分开。

CI 在真实 Linux Docker 引擎中验证宿主文件、秘密环境变量、根目录写入、Docker socket 和网络均不可访问；Windows/Mac 同时运行两平台适配和参数边界测试。本机引擎就绪与真实群聊能力仍单独核验。普通聊天只需讨论时不需要启动代码容器。

## 下载与首次安装

Windows：

```powershell
git clone https://github.com/Au-Cu/douyin-agent-bridge.git
cd douyin-agent-bridge
powershell -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1
```

Mac（Apple 芯片，原生 ARM64 Node.js）：

```bash
git clone https://github.com/Au-Cu/douyin-agent-bridge.git
cd douyin-agent-bridge
./install-mac.command
```

也可以从 [Release](https://github.com/Au-Cu/douyin-agent-bridge/releases/latest) 下载对应系统的源码 ZIP：Windows 选择 `windows-source.zip`，Mac 选择 `macos-arm64-source.zip`。解压后分别双击 `install.cmd` 或 `install-mac.command`；macOS 首次打开未签名脚本时可能需要在 Finder 中右键选择“打开”。安装包不包含 Node、账号信息、浏览器登录资料或模型权重。

安装器执行 npm ci，准备视频工具和本地转写模型。模型压缩包约 163 MB，解压后约 239 MB。下载会校验完整性，完成后直接复用。

首次使用 Codex、或检查提示未登录时，打开项目目录下的终端执行：

```powershell
npm run codex:login
```

选择用自己的 ChatGPT 账号登录，完成官方浏览器流程。已有可用登录通常会直接复用。Windows 登录后运行 `start.cmd`；Mac 运行 `start-mac.command`。官方登录说明：[Codex Authentication](https://learn.chatgpt.com/docs/auth)。

Mac 首次连接 Safari 前，在 Safari“设置 → 高级”中显示开发者功能，然后在“设置 → 开发者 → 自动化”启用“允许来自 Apple 事件的 JavaScript”，并在 macOS 弹窗中允许终端控制 Safari。设置位置见 [Apple 开发者说明](https://developer.apple.com/documentation/safari-developer-tools/developer-settings)。

Mac 使用普通 Safari 窗口及其当前个人资料的登录状态，而非独立的 Playwright 登录目录。若主号和助手号需要隔离，请先在 Safari 中切换到助手专用个人资料，再打开抖音窗口并登录助手号；不要使用退出后即丢弃登录态的隐私浏览窗口。程序只控制自己创建或核验过的窗口，不操作其他 Safari 标签页。

## 连接自己的抖音

1. Windows 双击 `start.cmd`（也保留了 `启动助手.cmd`）；Mac 双击 `start-mac.command`，打开 http://127.0.0.1:39361。
2. 点“打开抖音窗口”，登录自己的助手账号。Windows 使用独立 Edge 资料目录；Mac 使用上面选定的 Safari 个人资料。
3. 从手机主号给助手发一条消息。在项目窗口打开主号私信，点控制台“绑定当前会话”。绑定核验账号 ID，不靠昵称。
4. 点“创建调度聊天”，建立首个需求会话；之后会自动按需求继续、新建或找回。
5. 若需要派任务，点“读取本机聊天”，选择允许接收任务的聊天，填别名、加入名单并保存。可先留空，只使用视频学习。
6. 点“开始监听”，再从手机转发一条新视频。启动前的历史消息不会被当成新指令。

之后在手机私信里使用即可。所有新消息先贴“👌”表示收到；真正处理时只贴抖音原生“奋斗”（红头带、双拳的表情，平台名称为 [奋斗]）；任务与全部回复均完成后贴“🎉”或可用的完成表情。运行阶段不使用其他表情作为替代。排队不会显示运行，模型生成完但回复尚未发完也不会显示完成。当前只用表情表示进度，不主动发送定时或阶段状态文字。表情无法核验时保持静默并在面板记录，不重复点击或用文字刷屏。结果回到原会话，使用纯文本、短段落、换行和编号。

端口 39361 的面板可配置默认模型、推理强度、快速模式、自动分聊和上下文预算，也可立即新建或切换需求。

## 在抖音里怎么用

| 发送内容 | 行为 |
| --- | --- |
| 私信转发视频卡片 | 获取原视频，转写口播并分析全时段连续画面，保存学习资料 |
| “按刚才的视频，解释页面切换的具体做法” | 引用已保存的画面、口播和视觉观察回答 |
| `/派 网站项目 根据刚才视频修改首页并验证` | 交给允许名单中的“网站项目”，只带本需求的原片索引与图片附件 |
| `/状态` | 查看视频分析和任务进度 |
| `/设置` | 查看模型、强度、快速模式、密度和分聊配置 |
| `/模型`、`/模型 gpt-6.1-sol` | 查看当前登录提供的模型；填写完整 ID 切换，`默认` 恢复默认 |
| `/强度`、`/强度 Max` | 查看当前模型支持的档位或切换；支持中文与协议档位名称 |
| `/快 开`、`/快 关` | 明确开启或关闭当前模型支持的快速模式 |
| `/密度 2`、`/密度 4`、`/密度 8` | 更改后续视频读取帧率 |
| `/分聊 开`、`/分聊 关` | 自动按需求路由；关闭后仍执行上下文预算硬规则 |
| `/预算 48000` | 设置会话上下文预算，范围 4000–200000 tokens |
| `/新建 网站改版` | 新建独立需求并切换；标题可省略 |
| `/找 网站`、`/找` | 查看相关或近期需求目录与 ID |
| `/切换 需求编号` | 明确找回旧需求，例如 `/切换 2`；旧 ID 仍兼容 |
| `/续看`、`/续看 视频ID` | 从最近或指定视频的保存进度续做 |
| `/重连` | 重新读取本机当前助手登录，保留绑定、目标名单与进度 |
| `/重试 任务编号` | 恢复确定尚未提交的受阻要求，例如 `/重试 5`；结果不明的任务不能自动重跑 |
| `/中断 任务编号` | 立即中断该任务，绕过普通执行和设置队列，例如 `/中断 5` |
| `/忽略` / `/结束忽略` | 静默忽略后续消息，再静默恢复；忽略期间仅识别结束命令 |
| `/归档需求 编号` / `/恢复需求 编号` | 收起或恢复需求；Codex 同步原生归档，DSH 仅本地归档 |
| `/归档任务 编号` / `/恢复任务 编号` | 收起或恢复任务卡；恢复显示不会自动重跑工作 |
| `/同意 编号` 或 `/拒绝 编号` | 处理 Codex 对应的操作确认；具体内容可在控制台核对 |
| `/帮助` | 查看完整命令用法 |

不填写设置命令的参数只查看，不会自动切换开关。`/派给`、`/继续视频`、`/重新连接` 及已提供的英文别名继续兼容。非法命令或不支持的模型组合会明确报错，不会当作普通任务执行。

只有绑定主号的直接指示可以派任务。视频里的口播、字幕和其他素材不会被当成你的命令。没有配置目标聊天时，不会擅自把任务发给其他项目。

## 面板收纳与归档

“连接助手”在绑定、Codex、转写与监听全部就绪后默认折叠；模型与授权聊天配置在首次自定义后折叠。可以随时点标题展开，手动选择会即时保存到固定数据目录，重启后恢复。顶部连接状态保持显示。

需求、学习资料及任务卡均有归档与恢复按钮，各列表可切换“当前显示 / 已归档 / 全部”。任务还可按排队、运行、受阻、需核实、完成、取消或失败等状态筛选；选择“已完成”会自动包含归档记录。任务只有在执行及全部文字分段确认送达后才自动归档，恢复显示后的已完成任务不会再次自动收起。

需求归档会调用 [Codex 原生归档接口](https://learn.chatgpt.com/docs/app-server)，归档这个需求的助手聊天及续接聊天；恢复也同步恢复这些聊天。正在运行的助手聊天需先结束。授权名单里的共享目标项目聊天不会被连带归档。归档提交及结果会持久记录，断线或结果不明时保留需核实状态，不盲目重复请求。

归档资料和任务仅收起面板记录，原视频、完整视觉证据、记忆与送达记录仍保留。已提交的工作继续保留现场；确定未提交的任务会暂停。恢复任务只恢复显示，暂停工作需明确发送 `/重试 编号`，结果不明的执行仍不得自动重跑。任务卡按实际后端提供 Codex 或 DSH 原生聊天链接，需要本机安装对应应用。DSH 的原生协议没有归档接口，DSH 需求仅做可恢复本地归档，不伪报原生归档成功。

已归档的任务和需求另有“彻底删除”按钮，新旧两版面板均可使用。点击后先展示对象和关联记录数量，勾选永久删除说明后才能确认。删除任务会清理本机桥接中的请求、执行、完整分段回复、回执、重试和引用索引；删除需求还会清理其关联任务和本地需求记忆目录。原始学习资料、抖音消息、Codex／DSH 原聊天、项目文件、已有备份及其他独立任务中的副本保留。删除不能通过“恢复显示”撤销；恢复旧备份仍可能找回旧记录，这不是磁盘安全擦除工具。

执行、发送、中断或归档结果尚未核实的记录禁止彻底删除。确认期间记录变化需要重新确认；缓存清理若遇到文件占用，会保留待清理工作并在重启后续清理。仅保留不可逆消息指纹用于阻止旧消息被再次接收，编号计数持续递增，不复用被删除的任务／需求编号。若单独删除任务，所属需求的派生摘要和交接缓存会失效，后续从仍保留的原文重新整理；外部助手原聊天中的旧内容不会被清除。永久删除仅在本机面板提供，模型和抖音命令不能触发。

如果删除被“回复或表情送达尚未核实”阻止，点击任务或已归档需求上的“核实送达”。窗口会逐条列出完整文字分段、状态表情、原消息、最近核验结果；删除遇到这类阻塞也会直接打开该窗口。可以只读核验原聊天，或在抖音确认后手动标记已送达，也可明确放弃指定回执、不再发送。放弃不会伪报送达；放弃结果文字会将该操作标为已取消，执行结果保留。表情核验只读取原生菜单的本账号选中状态，不能重复点击表情。只有未归档、未中断且聊天仍有效的文字可经明确确认重发指定一段。

普通监听读到新历史时，会尝试按助手身份、完整正文、确切发送时间边界及原生引用核验不明文字；没有唯一证据仍保留待核实，历史记录缺少时间边界时需人工处理。确认操作会立即同步任务状态，避免“已确认收到”后仍无法删除。面板提示浮在视口右下角，滚动到任何位置均可看见，可手动关闭；长提示内部滚动，不强制页面回到顶部。

## 重复催办、分段回复与调度阻塞

在抖音长按助手以前的反馈并选择“回复”，直接写下新要求，助手会定位被引用消息、对应需求和原视频。长反馈只需回复其中任意一段，系统会把同次回复的所有分段一并交给 Codex；派发到允许的项目时也带上这些分段及原始视觉证据。历史反馈仅作参考，是否派发和目标项目仍由你本条消息决定。

新版发送时保存平台消息 ID。升级前的反馈通过完整文本与本地发送记录唯一匹配；找不到、存在歧义或无法核实全部分段时，会保留你的要求并提示重新指定，不猜测。引用已归档需求会建立独立的新需求并带上原资料，不恢复或重跑旧任务。

新识别的补充要求使用主任务编号加序号，例如任务 1 的补充依次为 1-1、1-2，下一个独立任务仍是任务 2。原有编号不会变化；`/中断 1-1`、`/重试 1-1`、`/归档任务 1-1` 和 `/恢复任务 1-1` 均可使用。

任务卡可直接“中断”；`/中断 编号` 走独立控制分支，普通执行、分类、设置队列和发送锁不会挡住中断请求。它会持久保存停止意图，取消对应的 [Codex 回合](https://learn.chatgpt.com/docs/app-server)、终止本任务的 FFmpeg 和转写工作，并阻止后续派发及未发送的回复。启动瞬间明确返回“没有活动回合”的拒绝会短暂退避，至多重试 4 次；网络或结果不明不会被当作成功。只影响指定任务，不杀共享 Codex 服务或其他聊天。已经发生的文件修改不会被撤销；已尝试发送的分段继续保留送达核实记录。中断后的旧执行不会通过重试或重启自动恢复，需要时发送新的要求。

`/忽略` 与 `/结束忽略` 本身不发文字、不贴表情。忽略期间，文本、视频和其他命令均不分析、不派发、不进入 Codex 上下文；本地只保存消息编号、时间等去重信息，不保存被忽略的正文。只有准确的 `/结束忽略` 恢复接收，状态跨重启保留。此前已经收到的任务不因此中断，面板的中断按钮仍可使用。

归档任务从后续重复、补充判断的候选中排除；异步判断期间发生归档也会作废旧关联。手动归档会让未提交的旧补充解除母任务关系，独立保存并暂停，需明确 `/重试 编号` 才继续；恢复显示不会重新挂回旧关联。原任务完成并自动归档时，之前已经收到的补充会解除母任务关系，按已有授权独立续做，不丢失先前的修改指示。命令回执、表情详情的展开状态不会因面板定时刷新而折叠。“数据与恢复”默认折叠，可手动展开并保存选择。

任务执行与回复交付分别记录。长回复标出“回复 1/3 段”和“末段”，最后一段核验送达后才贴完成表情；重启会保留发送进度。期间再次发送同样要求，直接关联原要求并回复“这项要求正在处理，没有重复启动”以及真实阶段或发送段数，不再次调用工作模型或加入需求历史。疑似重复的语义判断使用独立轻量会话。

对外使用持久递增编号和简短标题，例如“任务 5：修改首页动画”“需求 2：网站改版”，重启不重新编号。新任务登记时只通知一次编号和标题；后续结果、分段回复、状态和重试使用同一编号。面板按真实 operationId 关联任务、文字回复与三个阶段的表情回执，合并到一张任务卡内；命令回执和技术详情折叠显示。执行完成与表情送达分别核验，不能把贴表情失败当成任务没执行。

写入锁只针对具体 Codex 聊天。不同目标聊天可以并行，同一聊天的后续任务串行；本机其他项目不会触发全局等待。桥接已加载的聊天不会反复 resume；来自目标聊天其他写入者的真实冲突仍保留现场，不强抢写入权。

新增约束与修改保留为补充，原要求执行并交付后再处理；不能把颜色、数值、否定条件等变化吞掉。明确要求“重新做/重新执行/从头来”才作为新一轮；否定“不要重新做”不代表重做授权。

独立检查器与执行锁分开运行。`active writer` 冲突会保留真实原因并按 10/20/40/60 秒间隔退避，至多 6 次或约 5 分钟后暂停，不无限显示排队。仅确定未提交的任务可用 `/重试 编号` 恢复；已经提交、断线或结果不明的执行保留现场，不能自动重跑。发送 `/状态` 或查看面板可看到阻塞、等待确认、分段交付及“暂时无法确认运行状态”。检查器不主动发送文字通知。

任务卡的“写入调度”显示最近一次检查的时间和结果，以及下一次计划时间或暂停状态；展开可查看该任务持久保存的逐次记录。实际收到 Codex 已开始的确认后才显示开始执行；断线造成的结果不明会单独标出，不自动重跑。升级前只保存过最后一次结果的历史记录会标明缺少更早的明细，不推测过去的时间与原因。

## 需求路由和上下文预算

每条普通消息先进入一次独立的临时路由会话；配置、状态、批准等精确命令直接处理。路由仅收到新消息、最近 4 条交流、当前需求的短摘要、近期与相关需求目录，选择继续当前需求、新建独立需求或找回旧需求。视频先完成全时段视觉观察，再将视觉主题摘要加入这一次判断，不会“一条视频开一个对话”。

路由和摘要使用当前登录提供的轻量模型（优先 Luna）及低推理强度，关闭快速模式；不支持该模型时改用当前工作模型的低强度。它们每次新建临时会话，结束后卸载，不累积成长对话。找不到明确的旧需求或指代有歧义时先询问，可用 `/找` 和 `/切换` 明确定位。自动判断仍可能出错，面板和 `/状态` 会显示当前需求，随时可以纠正。

默认上下文预算为 48000 tokens。优先使用 Codex 的线程用量通知；暂未返回用量时用偏保守的 UTF-8 字节估算，并留出回复余量。在两轮之间检查预算，接近或超过后保存短交接记录，再为同一需求建立新的续接会话。即使关闭自动分聊也保留这条规则；不会为换会话中断正在执行的任务。

每个需求独立关联视频、交流和任务结果。旧长对话保留为历史需求并导出完整记录，首次续做时建立有交接的新会话。记录在 `data/needs/` 和本地 SQLite 中，更新或换号不删除；它们属于私人数据，不随发行包发布。超长输入保存为文件，模型获得完整读取入口，不截断用户要求。

## 本机切换 Codex 账号

额度不足或登录失效时，可以在同一台电脑的 Codex 中完成其他自有账号的登录，保留同一个 CODEX_HOME。默认文件型登录每 3 秒检查一次；检测到变化后重建桥接连接，无需重绑抖音、重新选择目标聊天或重新转发视频。

正在执行的任务会先结束，再切换连接。因登录或额度暂停的视频会复用已保存的原片和已完成视觉片段，连接恢复后续做。执行结果不明的派发任务保留“需要核实”，不会自动重复执行。

也可以在抖音发送 `/重新连接`，或在控制台点“重新连接助手”；`/继续视频` 会先重新读取登录再续做。使用系统凭据库、未触发文件变化检测，或同一账号额度恢复时，可用这些入口手动触发。桥接不会保存多个账号的密码或替你自动切换账号；新登录本身必须有效且有可用额度。

这是本机 app-server 连接的恢复，不会更改 Codex 的登录文件或复制令牌。官方协议见 [Codex App Server](https://learn.chatgpt.com/docs/app-server#auth-endpoints)。

## Mac 版的验证边界

PR #1 作者在 Apple 芯片 Mac 上报告了真实抖音绑定、文字往返、三段表情和本地解码/转写验收。这是原贡献的验收记录，不等于本次合并版的真实账号复核。Mac Safari 标签页、消息发送、引用与表情有自动化回归；视频提取、下载和全片理解仍应在自己的 Mac 上用真实视频核验，不能用测试通过代替账户收发验收。

## 改用 DeepSeek Harness

Codex 仍是默认后端，原有登录、模型组合、绑定、需求、知识库、队列和启动入口继续兼容。DSH 是显式选择的可选后端，不是额度不足时的自动替代。源码包不捆绑 DSH，也不要求 Codex 用户安装 DSH 或配置 API Key。

1. 按 [官方项目说明](https://github.com/deepseek-ai/deepseek-harness) 安装并登录本机 DSH，先确认原生聊天可用。受限聊天和视觉工作器固定验证版本为 0.2.1-rc.5；其他版本不会静默放宽工具限制。
2. 在面板“个人 Agent 的模型与需求对话”选择后端并保存，正常停止、重新启动助手后生效；也可在抖音发送 /助手 dsh 或 /助手 codex。已有需求继续使用原后端，预算续开也保留原后端；新需求使用当前后端。
3. 普通聊天在上方独立选择后端，从下一轮起生效，不要求跟随个人 Agent。每种后端各自保存 Agent / 普通聊天的模型、强度和快速配置。面板只展示该模式实际目录，不把 Codex 模型名直接交给 DSH。
4. 授权目标区可分别读取 Codex 和 DSH 聊天，仍须显式加入别名名单。保存的目标自带后端标识；混合名单不会被切换为另一家模型。原有 Codex 聊天 ID 不改写。

环境变量 BRIDGE_HARNESS 优先于面板保存值。PowerShell 启动方式：

```powershell
$env:BRIDGE_HARNESS='dsh'
npm start
```

macOS 终端：

```sh
BRIDGE_HARNESS=dsh npm start
```

若未找到启动器，可用 DSH_BIN 指定官方 CLI 的 lib/bin.js 或可执行文件。Windows 官方 npm .cmd 启动器会解析到其 JS 入口，消息不进入 shell。DSH_HOME 可指定你原有 DSH 登录目录。不要复制认证文件到源码或聊天。

适配边界：

- 通过官方 [ACP](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/acp/acp/README.md) 建立会话，桥接自有工具经受控 MCP 回调执行。权限请求只允许明确的本轮同意或拒绝；目标项目不会注入个人助手规则。
- 模型 ID 使用 provider/model，推理强度保留 DSH 实际公布的档位；high 不会映射成 medium。DSH 未提供快速服务层时拒绝开启，原 Codex 快速配置不会被覆盖。
- 初始连续画面与视频回看工具的图片实际作为图像内容提交。按所选模型检查图片能力，未确认支持时停止并保留原片与进度；不会只发文件名后声称已经看过。临时分类和视觉工作器不开放宿主文件、终端或项目修改工具。
- DSH 普通聊天使用独立 DSH_HOME 和空目录，只加载已验证的内置配置。模型工具限公开检索、计算、时间和可选的同一隔离容器；用户插件、技能、宿主文件、shell、电脑及项目工具关闭。认证由 DSH 可信凭据服务只读引用原登录文件，不复制、不写入提示词。自定义提供商或未验证配置可能不可用，会明确拒绝，不回退到完整权限进程。
- Codex 目标复用桌面共享 app-server。DSH 目标恢复原生会话的原工作目录；原生 ACP 仅允许恢复不被占用的会话，桌面仍占用时保留受阻状态，不删除锁或另建副本。桥接自己的不同 DSH 会话可以并行。
- DSH 不支持原生归档，面板和 /归档需求 仅作可恢复的本地归档，同时阻断补充路由；恢复不会重跑任务。原生链接使用 dsh://session/。
- 每轮提交先持久记录。取消通过 ACP 通知并等待原请求终止；连接丢失或结果不明会保留现场和同一会话的执行防护，不自动重复提交。

检查连接不消耗模型推理额度：先保存后端后运行 npm run doctor；也可用环境变量显式选择。npm run doctor -- --live-dsh 或 npm run test:dsh 才会使用你自己的 DSH 额度。自动化测试使用本地合成服务，不替代真实 DSH 登录和抖音账号验收。

## 固定提示词在哪里

固定规则放在 `prompts/assistant.md` 和 `prompts/visual.md`。程序在建立助手会话时主动注入会话级规则；已有助手聊天首次恢复时更新一次，不依赖模型碰巧打开 README。`prompts/router.md` 与 `prompts/memory.md` 负责临时分类与交接摘要。派给其他项目时，用 `prompts/task-reference.md` 说明如何读取视频，消息只带读取入口、简短摘要和原片索引，保留图片附件。目标项目聊天原有的规则不会被覆盖。

每轮只传用户新指示、是否允许派发，以及必要的视频资料。普通追问只带简短索引；需要细节时再查询笔记或原片。视觉观察和口播等实际视频证据仍会提交给 Codex。修改固定规则后重启助手即可生效；无需重建抖音绑定或聊天名单。会话级规则仍属于模型上下文，这项优化不表示固定规则完全不消耗额度。

摘要不是原文的替代品。每份交接保留用户原话、完整回复、原片及视觉证据的入口；摘要缺失、过期或与新指示不一致时要求读取原文。合成真实模型验收覆盖了颜色禁用条件、预算、精确验收标识的跨会话找回，以及同需求视频补充和跨主题视频区分。这些检查减少遗漏风险，不构成任意问题都能保证回答正确的承诺。

## 视频如何理解

- 默认每秒 4 帧，按完整时间轴逐段观察；可选每秒 2 或 8 帧。
- Codex 可取原始清晰帧、裁剪放大局部，或用每秒 8/12/16 帧细看短片段。
- 每段完成即保存，断线或额度不足时可续做。全片观察完成前不会冒称已经完整学习。
- 保留原视频、逐段视觉证据和本地回看命令。下游 Codex 任务获得初始视觉附件，也能按时间回看原片。
- 当前 Codex 接口接收有时间顺序的图片序列，不是原生 MP4 视频输入；极短暂的帧间变化仍可能遗漏。

本地工具参考 Qwen-MM-Plugins core 的职责边界，使用 FFmpeg 独立实现，不需要 Qwen API 或 WSL2 插件。

## 启停、端口与数据

```powershell
.\Start.ps1 -Port 39362        # 需要换端口时使用，配置会保存
.\Start.ps1 -NoOpen            # 后台启动，不打开控制台
.\Stop.ps1                     # 任务结束后执行，停止当前副本
```

启动和停止脚本会核验数据目录。同一 Windows 用户的不同代码副本默认读取同一套资料，已经启动时会打开已有面板；独立数据配置不会互相停止。`-Force` 仅用于确实需要中断的情况；结果不明的任务和发送操作不会自动重放。

Mac 使用 `start-mac.command` 和 `stop-mac.command`；终端中可运行 `node scripts/mac-launcher.mjs start --port 39362` 或 `node scripts/mac-launcher.mjs stop`。Mac 默认数据目录为 `~/.local/share/douyin-codex-bridge/data`；Safari 的登录数据由 Safari 自己管理，不包含在桥接快照中。Mac 启停同样会核验数据目录，避免误停其他资料实例。

从 0.12.1 起，Windows 默认使用固定目录 `%USERPROFILE%\.douyin-codex-bridge\data`，避开打包应用对 AppData 的文件重定向。桌面 Codex 内启动和双击 CMD 启动读取同一个位置，与源码或解压位置无关。面板“数据与恢复”显示实际路径。新目录为空时，优先发现旧 `%LOCALAPPDATA%\DouyinCodexBridge\data` 及 Codex 应用私有目录中的原资料；没有这些资料时再迁移当前副本的 `data/`。迁移保留旧目录，复制模型、浏览器资料、需求、知识和共享配置，并重定位证据路径。多套不同的旧资料不会自动合并；先停止旧助手和共享桌面服务，再用 `node scripts/storage.mjs --migrate-from "完整旧数据目录"` 明确选择一套。已有账号或记忆的目标不会被覆盖。

设置和记录即时写入采用 FULL 同步的 SQLite；配置另有原子写入的 JSON 镜像与上次有效副本。程序启动、正常停止和运行中每 30 分钟生成状态快照，保留最近 32 份，也可点“备份配置与记录”。快照包含配置、需求、学习索引和任务记录；原片和画面保存在固定目录内，Windows 登录资料也在其中，Mac 登录资料由 Safari 管理。需要完整离线备份时，正常停止后复制整个固定数据目录。数据库损坏时停止启动，不用空库替代，也不静默回滚到旧快照重放任务。

重启会恢复抖音窗口、绑定会话和此前开启的监听；此前手动暂停的监听保持暂停。启动前的历史消息不会作为新指令重放。平台若主动使登录失效，仍需重新登录，但保存的模型、需求、名单与学习资料不受影响。Codex 使用本机自己的登录，不复制认证令牌。

需要多套隔离账号或便携存储时，可在启动前设置 `BRIDGE_DATA_DIR` 为自己的固定目录；服务也接受 `--data-dir`。两套同时运行的实例必须使用不同数据目录和端口。测试使用独立目录，不能复用真实账号数据。

| 位置 | 用途 |
| --- | --- |
| `data/config.json`、`config.json.bak` | 用户绑定、目标名单与偏好的可读恢复副本；权威版本在数据库 |
| `data/browser-profile/` | Windows 的抖音登录资料；Mac 只保存专用 Safari 窗口的识别信息 |
| `data/bridge.sqlite` | 配置、需求、消息、发件箱、任务和知识索引 |
| `data/knowledge/` | 原视频、文字稿、连续画面、视觉记录和笔记 |
| `data/needs/` | 私人的需求交接、完整交流导出和超长输入 |
| `data/models/`、`data/runtime/` | 首次安装下载的模型和视频工具 |
| `data/backups/` | 配置、需求和执行记录的一致性状态快照 |

只监听本机 127.0.0.1。请勿把 data/、Codex auth.json、Cookie、私人视频或完整日志上传到 GitHub；公开问题请用脱敏或合成样本。

## 开发与验证

```powershell
npm ci
npm run setup:runtime
npm test
npm run test:portable
npm run release:check
npm run release:build
```

`test:portable` 使用合成 Codex 服务和全新的临时数据目录，不读取个人登录。真实组件检查需自行选择运行：

```powershell
npm run doctor -- --live-codex --live-asr
npm run test:live
npm run test:visual
npm run test:routing
npm run test:dsh
```

`npm run test:dsh` 会真的启动本机 DeepSeek Harness 的 ACP 会话并跑通一次工具调用，会消耗你自己的模型额度；只想检查连接可以运行 `BRIDGE_HARNESS=dsh npm run doctor`。`npm test` 里的 DeepSeek Harness 用例使用本地合成的 ACP 服务，不联网也不消耗额度。

CI 分别在 Windows 和 Apple 芯片 Mac 上构建，并核对两份发布包版本、源码清单和校验值一致。这些真实模型检查会使用自己的 Codex 额度；组件测试通过不等于每个抖音账号的真实收发都已验收。跨聊天正在被桌面端占用时，桥接不会强抢；不明执行结果不会自动重做。
